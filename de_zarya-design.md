# de_Hum (бывш. de_Zarya) — дизайн-документ карты CS2

**Название проекта:** **de_Hum** (рабочее имя аддона в файлах пока остаётся `de_mygame`, менять необязательно). Отсылка к гулу люминесцентных ламп — центральному элементу атмосферы. Альтернативы, если передумает: de_Vacancy, de_Static.
**Тип:** Competitive / Defusal (de_)
**Размер:** компактный, ~3000×3000 юнитов (маленькая карта, чтобы довести до конца)
**Тема:** ~~заброшенный приморский космодром~~ → **ПЕРЕЕХАЛИ НА BACKROOMS** (белый вариант, не классический жёлтый) — полная смена концепции, решено пользователем после того как блокаут органически превратился в лабиринт мелких комнат.
**Ава/иконка проекта:** сделана (555×312, PNG+JPG) — белый коридор в перспективе, потолочная плитка, гудящие лампы, надпись DE_HUM.
**Статус:** блокаут построен (лабиринтом, пользователь пересобирал сам), первый playtest пройден, спавны/planты/buyzone в процессе, свет и текстуры адаптируются под новую тему.

## Идея темы (АКТУАЛЬНО: Backrooms, белый вариант)
Бесконечный лиминальный лабиринт однообразных белых комнат — сама потеря ориентации это фича, не баг. Старое противопоставление "открытый космодром vs тесный ангар" больше не действует.
- **Стены:** белые, стерильный/больничный вайб (не жёлтый ковролин классических Backrooms).
- **Свет:** гудящие люминесцентные лампы (`light_omni`, холодный/зеленоватый оттенок), НЕ `light_environment`/skybox — открытое небо ломает атмосферу закрытого пространства. Можно позже добавить мигание через I/O-логику.
- **Layout:** существующий лабиринт из мелких комнат (собран пользователем вручную поверх исходного 3-полосного каркаса Mid/A-сторона/B-сторона) полностью соответствует новой теме, никаких переделок ради "читаемости" не требуется.
- **Геймплей:** механика defusal (бомба/планты/закупка) остаётся как есть, просто в новом сеттинге.

## Layout (историческая схема, ЧАСТИЧНО УСТАРЕЛА)
Изначальный каркас — 3 полосы (B-сторона / Mid / A-сторона), Mid открыт по всей длине с дверями на уровне 12 и 36 клеток от верха (сетка 64). Пользователь затем пересобрал внутренности полос в лабиринт мелких комнат (что теперь соответствует теме Backrooms). Общая топология (T-спавн внизу с выходами, CT-спавн вверху Mid, коннекторы к A/B) в целом сохранилась, но точная форма комнат — по последним скриншотам в Hammer, не по этой схеме.
```
   [Bombsite B]      [CT спавн]      [Bombsite A]
        |          (ротация оба)          |
   [B конн.] --- [ Mid ] --- [A конн.]
        |          |  |            |
   [B halls]    [ центр ]      [A main]
        \          |            /
              [ T спавн ]
              (три выхода)
```

## Принципы дизайна
- **Три выхода из T спавна** — атака выбирает направление, защита не закрывает всё.
- **CT спавн по центру сверху** — равное время до A и до B (честный баланс) — актуально, если решат сохранять конкурентную честность несмотря на тему Backrooms.
- **Коннекторы Mid→A и Mid→B** — обходы и ротации.
- **Компактность** — играбельно с ботами, реально доделать.
- Примечание: с переходом на Backrooms строгая симметрия A/B уже не главный приоритет — потеряться в лабиринте нормально для темы, лишь бы не ломало саму механику раунда.

## Порядок постройки
1. **Блокаут** — вся карта серыми коробками по схеме: пол, стены, спавны, два сайта, коридоры, Mid, коннекторы.
   - Прогресс: пол построен (верхняя грань на Z=0), 4 внешние стены периметра + потолок (Z=128→144) — замкнутая коробка. 1 `light_omni`, по 1 спавну `info_player_counterterrorist` / `info_player_terrorist`, 1 `info_player_start`.
   - **Первый успешный playtest пройден полностью**: Save As → F9 Build Map (Fast Compile) → CS2 → `map_workshop de_mygame de_mygame` → зашёл в игру и походил внутри коробки.
   - Дальше: делить эту коробку внутренними стенами на реальный layout (Mid, Bombsite A, Bombsite B, T-спавн с тремя выходами, коннекторы) вместо одной пустой комнаты.
2. **Логика игры** — entity: точки спавна T/CT (несколько на команду), зоны бомбы (defuse) на A и B, покупные зоны, границы карты (playable space).
3. **Тест с ботами** — гоняем, ловим кривые тайминги, двигаем стены.
4. **Свет + оптимизация** — базовое освещение по всей карте, настройка производительности.
5. **Детейлинг** — тема космодрома: текстуры, ракета, ангар, пропы. Кандидат на использование Blender (у пользователя 200ч опыта) для уникальных пропов — генерация геометрии, настройка масштаба/коллизии/импорта в ModelDoc.
6. **Публикация в Workshop** (опционально).

## Технический контекст
- CS2 Workshop Tools установлены и работают.
- Аддон создан: **de_mygame** (`...\content\csgo_addons\de_mygame\`).
- Файл карты: `de_mygame.vmap` в папке `maps` аддона.
- Работа ведётся в редакторе **Hammer** (запуск: Workshop Tools → Launch Tools → Asset Browser → иконка Hammer).
- Единицы: 1 юнит ≈ 2 см. Игрок: рост 72, ширина 32. Потолок комнаты ~128. Сетка блокаута: 64 (крупные операции — 512).
- Компиляция: горячая клавиша **`F9`** в Hammer (не в меню Map — там этого пункта нет) → окно **Build Map** → **Fast Compile** (быстро, без расчёта света — для проверки геометрии/масштаба) или **Full Compile** (медленнее, но считает реальное освещение — гонять только когда нужно оценить свет, не на каждой правке).
- Запуск в игре: обычный CS2 (не Tools) → консоль (`~`) → **каждую команду отдельным Enter** (не одной строкой через пробел, иначе движок не распарсит): `map_workshop de_mygame de_mygame`.
- **Важные грабли, уже пройденные:**
  - Первый Save As может незаметно сохранить файл под именем `untitled_1.vmap` вместо нужного — проверять заголовок окна Hammer.
  - Коробка обязательно должна быть полностью замкнута (пол+стены+потолок), иначе `leak` при компиляции.
  - Обязательно нужна точка `info_player_start` (генерик-спавн) в дополнение к T/CT-спавнам, иначе ошибка "No player start".
  - **Спавны T/CT будут "Invalid spawnpoint" (и из-за этого экран команд пишет «все укомплектованы»), если origin стоит вплотную на полу (Z=0)** — по офиц. документации Valve нужно **минимум 16 юнитов над полом** (ставили 32), плюс минимум 32 между спавнами и минимум 16 от стен. Дистанция по X/Y от стен НЕ помогает, если проблема в высоте Z.
  - `Fast Compile` не считает свет вообще — тусклая картинка ожидаема, это не баг сцены.
- Рабочая папка проекта (документация, заметки): `C:\Projects\MyCSMap`.
