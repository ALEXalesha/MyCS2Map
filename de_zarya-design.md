# de_Hum (бывш. de_Zarya) — дизайн-документ карты CS2

**Название проекта:** **de_Hum** (аддон в файлах называется `de_mygame`, менять не стали). Отсылка к гулу люминесцентных ламп — центральному элементу атмосферы. Альтернативы, если передумает: de_Vacancy, de_Static.
**Тип:** Competitive / Defusal (de_)
**Размер:** компактный, ~3000×3000 юнитов
**Тема:** ~~заброшенный приморский космодром~~ → **Backrooms** (белый вариант, не классический жёлтый). Полная смена концепции — решено после того как блокаут органически превратился в лабиринт мелких комнат.
**Ава/иконка проекта:** сделана (555×312, PNG+JPG) — белый коридор в перспективе, потолочная плитка, гудящие лампы, надпись DE_HUM.
**Статус: играбельна, опубликована в Steam Workshop.** Блокаут, спавны, планты, buyzone, свет, радар — всё готово и рабочее. Остаются мелкие доводки (см. «Открытые задачи» ниже) и опциональный детейлинг.
**Репозиторий:** Gitea `ALEXaloysha/CSMap`, ветка `main`. README.md в корне репо отображается под списком файлов на странице.

## Идея темы (Backrooms, белый вариант)
Бесконечный лиминальный лабиринт однообразных белых комнат — сама потеря ориентации это фича, не баг. Старое противопоставление «открытый космодром vs тесный ангар» больше не действует.
- **Стены:** белые, стерильный/больничный вайб (не жёлтый ковролин классических Backrooms).
- **Свет:** гудящие люминесцентные лампы (`light_omni`, холодный/зеленоватый оттенок), НЕ `light_environment`/skybox — открытое небо ломает атмосферу закрытого пространства. Можно добавить мигание через I/O-логику (не сделано).
- **Layout:** лабиринт из мелких комнат (собран поверх исходного 3-полосного каркаса Mid/A-сторона/B-сторона) полностью соответствует теме, переделки ради «читаемости» не нужны.
- **Геймплей:** механика defusal (бомба/планты/закупка) в новом сеттинге, без изменений по сути.

## Layout (историческая схема, форма комнат с тех пор менялась)
Изначальный каркас — 3 полосы (B-сторона / Mid / A-сторона), Mid открыт по всей длине с дверями на уровне 12 и 36 клеток от верха (сетка 64). Пользователь пересобрал внутренности полос в лабиринт мелких комнат. Общая топология (T-спавн внизу с выходами, CT-спавн вверху Mid, коннекторы к A/B) сохранилась, точная форма — уже не по этой схеме.
```
   [Bombsite B]      [CT спавн]      [Bombsite A]
        |          (ротация оба)          |
   [B конн.] --- [ Mid ] --- [A конн.]
        |          |  |            |
   [B halls]    [ центр ]      [A main]
        \          |            /
              [ T спавн ]
              (три выхода)
```

## Принципы дизайна
- Три выхода из T-спавна — атака выбирает направление, защита не закрывает всё.
- CT-спавн по центру сверху — равное время до A и до B.
- Коннекторы Mid→A и Mid→B — обходы и ротации.
- С переходом на Backrooms строгая симметрия A/B уже не главный приоритет — потеряться в лабиринте нормально для темы, лишь бы не ломало саму механику раунда.

## Что сделано
1. **Блокаут** — пол, стены, потолок, лабиринт комнат (пересобран вручную).
2. **Игровая логика** — несколько спавнов T/CT (Z ≥ 16-32 над полом), `info_player_start`, `func_bomb_target` на A и B, `func_buyzone` на T (TeamNum 2) и CT (TeamNum 3).
3. **Свет** — `light_omni` по комнатам лабиринта, `env_combined_light_probe_volume` для нормального освещения рук/оружия/динамических объектов.
4. **Nav Mesh** — сгенерирован через `point_nav_walkable` (см. «Открытые задачи» про грабли).
5. **Радар** — сгенерирован через сторонний тул RadGen (radargenerator.github.io), сохранён как «сплошное пятно» без деталей стен — осознанное решение, вписывается в тему (карта не помогает ориентироваться).
6. **Тест с ботами** — работает, `custom_bot_difficulty` регулирует сложность.
7. **Публикация в Steam Workshop** — сделана.

## Открытые задачи / известные грабли
- **Buyzone не покрывает всю комнату спавна** («bot spawned outside of a buy zone» в логе) — нужно растянуть brush на всю комнату спавна с запасом.
- **Максимальный `custom_bot_difficulty 3` даёт skill ≈ 0.25**, не 1.0 — возможно, это практический потолок через штатные конвары, не до конца исследовано.
- **Мигающий свет** для ламп ещё не сделан (можно добавить I/O-логику позже).
- **Детейлинг** ещё предстоит: более тематические текстуры под Backrooms (ковролин на полу и т.п.), возможно уникальные пропы через Blender (у пользователя 200ч опыта — реальный вариант для генерации геометрии, с настройкой масштаба/коллизии/импорта в ModelDoc).
- Периодически стоит проверять, что радар в Workshop-версии совпадает с локальной — расхождение бывает, если публикация ушла раньше, чем в RadGen нажали `Save Radar Image`, или до пересборки карты.

## Технический контекст
- Аддон: **de_mygame** (`...\content\csgo_addons\de_mygame\`), файл карты `de_hum.vmap` в папке `maps`.
- Работа в редакторе **Hammer** (запуск: Workshop Tools → Launch Tools → Asset Browser → иконка Hammer).
- Единицы: 1 юнит ≈ 2 см. Игрок: рост 72, ширина 32. Потолок комнаты ~128. Сетка блокаута: 64 (крупные операции — 512).
- Компиляция: горячая клавиша **`F9`** в Hammer (в меню Map этого пункта нет) → окно **Build Map** → **Fast Compile** (быстро, без света) или **Full Compile** (со светом и кубмапами, дольше).
- Запуск для полноценного теста (боты, nav, кастомные конвары): **обычный CS2, не `-tools` режим** — часть команд (например, `nav_generate`) недоступна при запуске через Hammer/Load Map In Engine. Консоль (`~`) → каждую команду отдельным Enter → `map_workshop de_mygame de_hum`.

**Уже пройденные грабли (не наступать снова):**
- Первый Save As может незаметно сохранить файл под именем `untitled_1.vmap` — проверять заголовок окна Hammer.
- Коробка обязательно должна быть полностью замкнута (пол+стены+потолок), иначе `leak` при компиляции.
- Обязательно нужна точка `info_player_start` в дополнение к T/CT-спавнам, иначе ошибка «No player start».
- Спавны T/CT становятся «Invalid spawnpoint» (экран команд пишет «все укомплектованы»), если origin стоит вплотную на полу — нужно минимум 16 юнитов над полом (ставили 32), минимум 32 между спавнами, минимум 16 от стен.
- `Fast Compile` не считает свет — тусклая/чёрная картинка ожидаема, это не баг сцены.
- **Nav Mesh:** авто-генерация падает с `>>NAVGEN: Skipped... no walkable seeds present`, даже если весь лабиринт проходим. Фикс — сущность `point_nav_walkable` (Hammer-эквивалент старой `nav_mark_walkable`), достаточно одной точки в связном пространстве.
- **Bot skill:** `bot_difficulty` не влияет на реальный навык (лог всегда пишет `bot skill = '0.05'`). Реальный рычаг — `custom_bot_difficulty <0-3>` (без знака `=`, обычный конвар).
- **Чёрные руки/оружие** — отсутствие Light Probe Volume/Cubemap (`env_combined_light_probe_volume`). У сущности куб (Box Mins/Box Maxs, тянуть за хендлы) и сфера (радиус, через Transform→Scale) — независимые параметры, легко перепутать.
